## 色域边界追踪与软压缩（Go 标准库实现）

对比两种设备色域：源设备为 sRGB（D65），目标设备为窄色域显示器，其
三原色在 XYZ 中向 D65 收缩到 0.4 倍，并重新求解 RGB->XYZ 矩阵，使纸白
`(1,1,1)` 仍精确映射到 D65。全部代码仅使用 Go 标准库（`math`、`os`、
`fmt`、`encoding/csv`、`image/png`、`strconv`、`testing`）。

### 方法

- 颜色链路：sRGB -> 线性光 -> XYZ -> CIE L*a*b* -> LCh，全部带逆变换。
- 边界追踪 `Gamut.maxChroma`：固定 L 和色相，对彩度做 60 次二分，利用
  可行彩度区间从 0 起连续的性质，求色域边界上的最大彩度 `C_boundary`。
- 朴素硬裁剪 `Gamut.clipLab`：在设备线性 RGB 上逐通道 clamp 到 [0,1]，
  不保持色相，投影到 RGB 立方体别的面/棱上会产生霓虹色跳变。
- 软压缩 `compressChroma`：固定 L 与色相，膝点 `k=0.85*C_boundary` 以内
  原样保留；膝点以上用 C1 连续的理性函数平滑滚降，并以边界彩度为渐近线：
  `C' = k + (C-k)(B-k)/((B-k)+(C-k))`，永不越界、绝不改变色相。
- 色差用 CIEDE2000（`ciede2000.go`，kL=kC=kH=1）。

### 测试轨迹

每条轨迹 257 个采样，在 Lab 中从纸白 L=100 线性插值到高饱和原色：
红（h≈40°）、蓝（h≈306°）、青（h≈197°）。

### 运行

```
go test ./...
go run .
```

### 产物（artifacts/）

- `boundary_map.png`：L*=50 的 LCh 极坐标边界图，sRGB（灰虚线）与窄色域
  （黑实线），叠加三条原始轨迹及其硬裁剪（橙）/软压缩（绿）结果。
- `hue_continuity.png`：三条轨迹逐采样的色相跳变，硬裁剪出现尖峰，软压缩
  全程为 0。
- `boundary_L50.csv`：每 2° 一个色相的两设备边界彩度。
- `track_{red,blue,cyan}.csv`：每点 Lab、色相、是否在色域内、ΔE00、
  色相步长与色相偏移。
- `metrics.txt`：最大色差、最大色相偏移/跳变汇总。

### 关键结论

- 软压缩在三条轨迹上色相偏移与逐点色相跳变均为 0，且所有结果都落在
  目标色域内；硬裁剪最大色相偏移红轨约 28.7°、蓝轨约 13.8°。
- 蓝轨软压缩最大 ΔE00≈29.1，低于硬裁剪的 ≈35.7；保色相的同时色差更小。
