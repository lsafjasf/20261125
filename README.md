# vqaudit — 双参数编码伪影空间审计（Go 单模块）

场景：同一编码任务换参数后平均 PSNR 只降一点，但客户先看到**暗部色带**。
均值指标会掩盖局部、低能量的色彩转换伪影。本工具对参考帧与两套编码参数
输出做逐帧、逐 tile 的空间分布对比，并把伪影分成两类：

- `coding`（编码伪影）：残差能量集中在 8px 变换块边界上，`blockScore`
  （边界平均绝对差 / 内部平均绝对差）≥ 1.8，指向 QP、码率分配、去块滤波。
- `conversion`（色彩转换伪影）：仅在**暗部平滑区**（Y ≤ 64 且双向梯度
  ≤ 2）统计。检测到量化色带步长（相邻跳变 ≥ 2、两侧平坦）或色度漂移
  （Cb/Cr RMSE 超门限），指向色彩矩阵（BT.709/601）、全/有限范围、
  量化位深与抖动。
- `mixed`：同一 tile 两种机制同时触发；`none`：残差低于噪声门限 1.0。

关键设计：PSNR 按全图计算，但严重度排名对暗部色带与色度漂移加权，
因此“PSNR 几乎不变、色带先暴露”的参数集会被正确排到检查清单最前面。

## 用法

```bash
go build -o vqaudit .
./vqaudit -ref ./frames/ref -a ./frames/paramA -b ./frames/paramB \
  -label-a paramA -label-b paramB -out ./audit-out -top 10
```

- 三个目录中的帧按文件名**自然排序**对齐（`frame_2` 在 `frame_10` 前），
  帧数不一致直接报错，避免错帧对比。
- 支持 `.png`/`.jpg`；统一转全范围 BT.709 YCbCr（4:4:4 全分辨率计算，
  不做色度下采样，避免分析本身引入色带）。
- `-now 2026-11-25T08:00:00Z` 可固定运行时间，保证 run id 与报告可复现。

## 输出（复测顺序）

写入 `-out` 目录，全部为确定性排序：

1. `report.json` — 两套参数的汇总、逐帧 PSNR/色带步数/块边界分/色度
   RMSE/tile 分类计数，以及 inspection 排名和 `nextCheck`。
2. `inspection.csv` — 严重度最高的 N 个 tile：参数集、帧号、tile 行列、
   像素坐标框、分类、各指标与排查建议。
3. `manifest.json` — 复测清单：配置、全部输入文件的 SHA-256、帧对齐顺序、
   Go 版本与输出文件列表。用同一批输入重跑应得到字节一致的报告。

## 如何读结果

- 先看 `nextCheck`：明确指出**下一次应检查的参数集、帧、tile 像素区域**
  及对应排查方向（编码链路或色彩转换链路）。
- 汇总行比较两套参数的 `bandSteps`、`tilesConversion`、`blockScore`；
  逐帧行给出 `dPSNR(B-A)` 与两类伪影计数，定位问题出现的起始帧。
- 门限集中在 `metrics.go` 常量区，可按素材特性调整后用 `go test` 回归。

## 测试

```bash
go test ./...      # 含端到端确定性、双类伪影分类、自然排序、帧数校验
```

合成用例构造了两种对照：温和对称噪声（PSNR 略降但零结构化伪影）与暗部
海报化+蓝偏（PSNR 几乎不变但产生大量色带），验证工具能复现客户反馈的
“均值无感、暗部先有色带”现象。
