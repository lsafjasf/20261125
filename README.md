# 音频取证 · 多证据复核台

一个只用 Go 标准库实现的取证页面。旧逻辑把底噪变化直接标红；本实现把上下文突变、相位接缝和重复样本分开取证，并通过旧页/新页同一时间网格的统计对照说明修复前后结果。

## 运行

```bash
go run ./cmd/forensic -addr 127.0.0.1:8080
```

打开 `http://127.0.0.1:8080/`。页面会自动载入内置演示样本，也可以拖入或选择 WAV 文件。

```bash
go test ./...
```

测试覆盖 WAV 原始字节保持、底噪单独不标红、相位接缝、精确重复片段、灵敏度增量重算、统计网格对齐，以及 HTTP 原始音频回放。

## 证据模型

### 固定区间网格

分析先把音频切成固定帧区间（默认 2048 样本窗、1024 样本步长，短采样率自动减半）。区间边界、数量、起点和步长在一次分析中固定。旧页规则和新页多证据规则都读取同一个 `Intervals` 数组，因此 `legacyStats` 与 `stats` 可以直接对齐比较。

### 上下文窗口

每个区间取左右各约 2 秒的上下文窗口，并留出约 0.2 秒保护带。左右窗口的频带能量中位数构成趋势预测，局部窗口只与预测残差比较，同时用两侧窗口内部的鲁棒离散度归一化。

- 缓慢底噪漂移会被趋势吸收。
- 硬台阶、突然静音或突然增响会产生上下文证据。
- 上下文证据单独最多贡献 `0.28`，而最低红色阈值是 `0.40`，所以“底噪变了”本身永远不会标红。

### 相位证据

相位证据使用 STFT 相邻帧的相位增量，并与上一帧相位增量对照，而不是假定每个频点都在整数 bin 上。这样持续音不会因为非整点频率产生假跳变；真正的接缝、反转或样本拼接会产生相对相位残差。立体声还会比较通道间相位差的历史增量。

相位分数会结合调性权重，并用上下文相位跳变基线归一化。宽带噪声本身相位不稳定，其高基线会压低相对分数。

### 重复样本

重复检测对滑窗 PCM 指纹做桶匹配，再逐样本比较解码后的精确 `float64` 位模式。连续匹配窗口会合并成复制区间，报告两段时间和相似度。低能量静音窗口被排除，避免自然停顿被当作重复。

指纹只用于找候选；最终是否算重复仍由逐样本一致性决定。

## 灵敏度只重算相关区间

区间置信度是不可变分数，分类规则为：

```text
flagged = confidence >= cutoff(sensitivity)
cutoff(s) = 0.85 - 0.45*s
```

灵敏度变化时，只重新分类置信度落在新旧 cutoff 之间的区间。区间索引按分数预排序，通过二分查找定位候选段；其他区间的红色/非红色结论直接复用。响应会返回：

- `recomputedIntervals`：实际重新检查的区间数；
- `recomputedRanges`：这些区间合并后的时间段；
- `changes`：真正发生翻转的区间；
- `before` / `after`：同一网格上的前后统计。

页面根据 `changes` 原地更新初始分析结果，不重新拉取整份区间数据。

## 原始录音不降噪

- `audio.WAV.Original` 保留上传的原始字节，只读。
- 分析使用独立的归一化 `Interleaved` 副本，不回写原始字节。
- `GET /api/sessions/{id}/original` 直接返回原始字节，并带 `X-Audio-Processing: none` 与 `X-Original-Sha256`。
- 服务没有“降噪后音频”端点，也不做有损转码。播放器读取的就是原始文件。
- SHA-256 在上传解析时计算，之后用于页面与 API 校验。

## HTTP API

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/api/demo` | 创建内置演示会话 |
| `POST` | `/api/sessions?name=...` | 上传 WAV 原始请求体 |
| `POST` | `/api/sessions` | 上传 `multipart/form-data`，字段名 `audio` |
| `GET` | `/api/sessions/{id}` | 获取当前分析结果 |
| `GET` | `/api/sessions/{id}/original` | 原始 WAV 字节，支持 Range |
| `GET` | `/api/sessions/{id}/waveform?buckets=2400` | 可视化峰值 |
| `POST` | `/api/sessions/{id}/sensitivity` | `{"sensitivity":0.55}` 增量重算 |

## 目录

```text
cmd/forensic/            HTTP 入口
internal/audio/          WAV 解析、原始字节保留、PCM 辅助编码
internal/analysis/       FFT、上下文/相位/重复证据、增量重算、统计
internal/demo/           确定性演示录音
internal/server/         HTTP、会话、内嵌页面
internal/server/static/  纯 HTML/CSS/JS 取证页
```

## 限制

- 支持 PCM 8/16/24/32-bit、IEEE float 32/64-bit 的 RIFF/WAVE，含 `WAVE_FORMAT_EXTENSIBLE` 包装。
- 单文件上限 256 MiB，时长上限 15 分钟。
- 解码后的分析样本上限 1 亿个，超出会被拒绝以避免内存风险。
- 会话保存在内存，默认 2 小时过期；服务重启后清空。
- 重复检测针对精确重复样本；经过有损压缩或重采样的“近似重复”不会被报成精确复制。
