# hdrmeta — 可复核的 HDR 静态元数据候选值推导

当母版没有可信的 MaxCLL / MaxFALL 报告时，本工具从**实际解码出的画面像素**
重新推导候选值，并同时给出严格定义值与抗误报的稳健候选值，供人工复核。

- 纯 Go 标准库实现（`image/png`、`image/color`、`math`、`sort` 等），
  不调用 ffmpeg、MediaInfo、EXR 工具等任何外部媒体程序。
- 输入为 PQ（SMPTE ST 2084）编码的 PNG 抽帧（支持 16 位容器承载 10/12 位信号）。
- 自带合成样本生成器，复现「故意过亮 / 全黑 / 字幕高光」三类误报场景。

## 快速开始

```bash
go test ./...                                  # 单元测试（PQ 锚点 + 误报场景）
go run ./cmd/hdrmeta demo -out testdata/demo   # 生成 4 张合成 PQ 帧
go run ./cmd/hdrmeta analyze -depth 10 testdata/demo/*.png
go run ./cmd/hdrmeta table -depth 10 -clip 1000
```

## 代码值、实际 nit 与裁切点的关系

1. **代码值（code value）**：容器里的整数，范围由位深决定（10bit 为 0–1023，
   12bit 为 0–4095）。它本身不是亮度，只是 PQ 非线性光传递函数的输入。
2. **归一化信号 N**：`N = code / (2^bitDepth − 1)`，范围 0–1。
3. **实际 nit（cd/m²）**：对 N 施加 PQ EOTF（SMPTE ST 2084）得到线性光亮度，
   `N=1` 对应 PQ 标称峰值 10000 nit。关键锚点：

   | 含义 | 10bit 代码值 | 实际 nit |
   |---|---:|---:|
   | 黑位 | 0 | 0 |
   | 约 100 nit（SDR 白） | 520 | 100.0 |
   | 约 203 nit | 594 | 203.0 |
   | 1000 nit 显示峰值 | 769 | 998.9（量化后） |
   | 4000 nit | 923 | 3988.0（量化后） |
   | PQ 满峰 | 1023 | 10000 |

4. **裁切点（clip point）**：由目标显示峰值决定。例如 1000 nit 显示器上，
   代码值 769 ≈ 998.9 nit 仍可显示，**代码值 770（≈1007.9 nit）起所有像素
   被硬裁切到 1000 nit**，码值再高也不会更亮，只会丢失高光层次。
   `table` 子命令逐码列出 nit 与 `CLIPPED` 标记，可直接复核。

注意量化效应：整数码值无法精确命中任意 nit（如码 769 是 998.93 而非整 1000），
因此工具报告「实测 nit」与「对应码值」两列，避免把取整误差当成画面问题。

## 推导方法

### 1. 像素级亮度

每个像素的 R/G/B 码值分别经 PQ EOTF 线性化，再按 BT.2020 非恒定亮度
系数在**线性光域**加权得到亮度 Y：

```
Y = 0.2627*EOTF(R) + 0.6780*EOTF(G) + 0.0593*EOTF(B)
```

### 2. 逐帧统计

- `max`：帧内单像素最大亮度（CTA-861.3 帧 MaxCLL 输入）。
- `mean`：全帧平均亮度（CTA-861.3 帧 FALL 输入）。
- `p99.9` / `p99.99`：最亮 0.1% / 0.01% 像素的均值，稳健指标。
- 超过 1000 / 2000 / 4000 nit 的像素计数，以及裁切像素占比。

### 3. 高光区域统计

以 `gate`（默认 1000 nit）做阈值，用 4-邻域泛洪提取连通域，记录每个区域的
像素数、面积占比、包围盒、峰值/均值 nit 与对应码值，并按 `area`
（默认帧面积的 0.1%）标记 `qualified` 或 `speckle/subtitle`。
这一步把「真实大面积高光」与「字幕、镜面火花、孤立热像素」区分开。

### 4. 序列级四个候选值

| 候选 | 定义 | 用途 |
|---|---|---|
| 严格 MaxCLL | 所有帧单像素最大值的最大者 | CTA-861.3 字面定义，不隐藏任何真实亮点 |
| 严格 MaxFALL | 所有帧平均亮度的最大者 | CTA-861.3 字面定义 |
| 稳健 MaxCLL | 各帧 p99.9 的最大者 | 抵抗孤立热像素/小字字幕膨胀 |
| 区域 MaxCLL | 面积合格区域内的峰值 | 只承认占足够画面比例的高光 |

最终上报值按元数据惯例向上取整（≤1000 nit 取 50 的倍数，>1000 nit 取 100 的
倍数），**永不向下取整**，并同时反算回码值，保证可复核、可复算。

## 误报检查（三类合成样本）

`demo` 生成 128×128 的 16 位 PQ PNG：

1. `frame02_overbright.png`：32×32（6.25% 画面）4000 nit 大块 →
   区域判定 `qualified`，区域 MaxCLL 如实给出 ~4000 nit。
2. `frame03_black.png`：全黑 → 全部候选为 0，无任何高光区域，不会凭空
   产生元数据。
3. `frame04_subtitle.png`：2×6（0.073% 画面）4000 nit 字幕字形 →
   严格 MaxCLL 仍诚实记录 ~4000 nit（画面里确实有这么亮的像素），
   但区域标记为 `speckle/subtitle`、区域 MaxCLL 为 0、稳健 MaxCLL 明显
   低于 4000 nit，复核者可据此拒绝把字幕峰值写进母版元数据。

对比典型输出（仅黑帧 + 字幕帧）：

```
严格 MaxCLL  : 3987.98 nits -> 4000 nits   （字面定义，保留事实）
稳健 MaxCLL  : 2844.53 nits -> 2900 nits   （p99.9 已被暗场稀释）
区域 MaxCLL  :    0.00 nits ->    0 nits   （无面积合格区域）
```

## 实际母版接入方式

用任意色彩管线把母版抽帧为 PQ PNG（10/12 位信号可左对齐装进 16 位 PNG），
保持目录顺序后执行：

```bash
go run ./cmd/hdrmeta analyze -depth 10 -clip 1000 -gate 1000 -area 0.001 frames/*.png
```

抽帧环节在本工具之外完成；本仓库内的全部计算只依赖 Go 标准库，
可在无网络、无外部媒体程序的环境中直接 `go test` / `go run` 复现。
